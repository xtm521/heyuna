# 合芽钱包 · Apple 原生版

独立、自托管的 iPhone 与 Mac 钱包。界面使用 SwiftUI，钱包逻辑放在共享 `WalletKit` 中；不嵌入研究客户端，不读取训练、编程助手、项目或对话状态。

**当前是开发版本，不是已上架产品。** 编译、模拟器、真机、签名、上传、审核和公开发布分别验收，记录见 [APP_STORE.md](APP_STORE.md)。当前发布账户为个人账户；组织会员等发行门槛尚未完成。

## 范围

| 网络 | 原生资产 | 恢复路径 / 账户范围 |
| --- | --- | --- |
| Bitcoin 主网 | BTC | BIP84，账户 `m/84'/0'/0'`；接收 `/0/*`、找零 `/1/*` |
| Bitcoin Signet | 测试 BTC | BIP84，账户 `m/84'/1'/0'`；接收 `/0/*`、找零 `/1/*` |
| Ethereum 主网 | ETH | `m/44'/60'/0'/0/0`，单账户、单地址 |
| Sepolia | 测试 ETH | 与主网相同的 `m/44'/60'/0'/0/0`，通过链身份区分 |
| 合芽研究网 | 暂不可操作 | 仅显示未配置状态；尚未开放可信网络清单导入、余额查询或交易 |

首版仅处理普通原生币转账。没有代币、NFT、合约交互、兑换撮合、跨链桥、法币买卖、理财、挖矿、训练或完成任务发币入口；不提供价格或收益承诺。EVM 拒绝向已部署合约发送，钱包连接协议及任意消息签名不在本版范围内。

## 创建、恢复与联网

1. 创建生成 **24 个英文 BIP39 单词**；导入接受校验通过的 **12 或 24 个英文单词**。**不支持 BIP39 附加 passphrase**（有时被称为额外密码或第 25 个词）。原钱包使用附加 passphrase 时，直接导入单词不能恢复原地址。
2. 备份核对后写入本设备系统 Keychain。查看助记词及签名须经系统身份验证；没有服务端恢复、云同步或跨 App 密钥共享。
3. 初次启动不配置远程服务、不自动联网。用户分别填写所选网络的 **HTTPS** RPC 或 Esplora 地址，再主动查询或预览交易。URL 不接受内嵌用户名、密码、查询参数或片段。
4. Bitcoin 核对创世区块哈希，EVM 核对链 ID 和创世区块哈希。核对可拒绝误接网络，不能证明一个恶意节点对余额、费用或确认数诚实。
5. 金额未查询成功时显示“—”。预览有效期为 120 秒，签名前重新核验网络和相关余额状态。签名前的公共状态复查完成后，系统认证须在 30 秒离线签名许可内完成。广播前持久化哈希和已签名公开交易字节；结果不确定时不自动重发，可核对哈希后由用户再次认证并重新广播同一笔原始交易，不会重新选币或签名一笔新支付。

Bitcoin 当前仅恢复账户 0 的 Native SegWit 描述符，扫描接收及找零分支，**每分支最多 200 个地址（索引 0–199），连续 20 个未使用地址即停止**。任一分支在此上限内未达到 gap 20，整次查询失败，不将截断扫描显示为完整余额。每个地址的 UTXO 返回条目、整次扫描选中的 UTXO 和下载的不同原始交易均各限 100；超过限制即拒绝结果。间隔超过 20 个空地址、扫描范围外、其他账户、其他脚本类型或其他派生路径中的资金可能不可见。EVM 不扫描其他地址索引。**不能将本版称为任意钱包的完整恢复工具。** 收款目前展示接收分支索引 0，可能重复使用地址。

Bitcoin 的 Esplora 读取由应用自己的 `URLSession` 适配器完成，拒绝重定向；单次 GET 请求最长 15 秒，同一适配器实例有 90 秒期限和 1,200 次请求上限，按接口逐字节限制回包大小。它核对原始交易的 txid、vout、金额、脚本，以及节点报告的区块高度和哈希，并重新读取扫描锚点。BitcoinDevKit 只在本地处理描述符、交易解析、PSBT 和签名，不负责 HTTP 查询。

这些检查仅证明节点返回内容之间符合当前检查规则，**不是 SPV、工作量证明或完整共识验证**；余额与确认数仍依赖用户选择的节点。网络服务可获知 IP、查询地址、关联脚本及交易。当前 BTC 展示并花费的是节点报告至少 6 次确认且通过上述检查的 UTXO，未确认或少于 6 次确认的资金不计入该可用余额；费率及总费用设有本地上限，不支持一键全额转出。节点身份、余额、广播、确认是不同状态。

## 平台与开发

- iOS **17+**，macOS **15.5+**；后者来自当前锁定的 BitcoinDevKit 预编译产物实际最低系统要求。
- 当前锁定依赖见 [Package.swift](Package.swift) 和 [Package.resolved](Package.resolved)。第三方来源及许可证保留在 `Vendor/` 和依赖包中，不以合芽原创声明覆盖。
- 共享库测试入口：在仓库根目录运行 `swift test --package-path apps/apple-wallet`。此命令是复现入口，不表示已有测试通过证据。
- 应用工程、资源、权限和签名配置由本目录中的 Xcode 工程管理；最终归档必须检查 `PrivacyInfo.xcprivacy` 已随两个平台 App 打包。

仅使用专门生成的测试助记词测试。不要将真实助记词放入日志、测试夹具、截图、命令行参数、问题附件或 Git 提交。详细边界见 [SECURITY.md](SECURITY.md)，隐私材料草稿见 [PRIVACY.md](PRIVACY.md)。

打开 `HeyunaWallet.xcodeproj`，或在仓库根目录运行 `./apps/apple-wallet/script/build_and_run.sh` 启动 Mac 开发版本。脚本默认临时签名，只供本机界面测试；使用系统受保护 Keychain 的实际行为还需正确开发签名与设备验收。

实际本轮证据见 [Evidence/verification.json](Evidence/verification.json) 与 [Evidence/README.md](Evidence/README.md)。
