# 钱包安全边界与验证要求

本文件描述开发版的代码边界及发行门槛，不构成独立审计报告，也不宣称资金损失不可能发生。尚未完成的验证保持 `pending`，见 [APP_STORE.md](APP_STORE.md)。

## 资产与隔离

- 助记词控制 BTC 和 EVM 私钥，丢失且无有效离线备份可能永久失去资产。没有运营方代管、密码重置或远程找回。
- 独立 App、独立沙箱、独立 Keychain service；没有 App Group、共享钥匙串或云同步配置，不读写共训客户端、编码助手及其状态。
- 助记词在系统 Keychain 中以非同步条目保存，访问控制为 `.userPresence`：系统可用生物识别或设备凭据验证身份，**不是仅限生物识别**。
- iOS 使用 `WhenPasscodeSetThisDeviceOnly`；macOS 使用 Data Protection Keychain 的 `WhenUnlockedThisDeviceOnly`。设备绑定条目不能当成可迁移备份。系统凭据变化、设备丢失、卸载或钥匙串不可用的恢复行为须在发行前真机验证。
- 不宣称 secp256k1 私钥始终在 Secure Enclave 内签名。助记词展示、派生和签名会在应用进程内存中出现；尽量缩短生命周期并清理可变缓冲区，但 Swift 字符串、依赖内部副本及运行时不提供完整内存零化证明。
- 公共地址、BTC 公共描述符、节点地址、交易记录存于 App 支持目录；目录排除系统备份，文件权限限制为当前用户，iOS 使用完整文件保护。公共描述符也具有隐私敏感性，不能当作无害日志输出。

## 签名与链状态

- 支持 BTC BIP84 账户 0 及 EVM `m/44'/60'/0'/0/0`，不接收任意 DApp 签名请求、不签任意合约调用。
- 预览展示网络、地址、金额、费用和总额。签名前再次核对端点身份、余额及 UTXO 或 nonce；过期、切网、进入后台或取消后丢弃待签状态，非活跃场景显示隐私遮罩。需要以实际 UI 和并发测试确认这些约束，文档不替代测试。
- Bitcoin 使用应用自己的 `URLSession` Esplora 适配器读取网络数据，BitcoinDevKit 只在本地处理描述符、原始交易解析、PSBT 和签名；EVM 使用锁定密码库。禁止自创密码算法或将研究密码方案用于真实资产。
- BTC 扫描接收及找零分支各最多 200 个地址，并要求在上限内达到连续 20 个空地址的停止条件；否则整次查询失败，不返回截断余额。每地址 UTXO 返回条目、整次选中 UTXO 及不同原始交易各限 100。读取适配器拒绝重定向，单 GET 最长 15 秒、实例期限 90 秒、请求最多 1,200 次；流式回包按接口限制大小。
- 对候选 UTXO 核对原始交易 txid、vout、金额和脚本，交叉核对节点报告的区块高度/哈希并在扫描结束重新读取锚点。**这不是交易包含证明、SPV 或区块工作量验证**，不能阻止一个节点一致地伪造数据或隐瞒资金。
- 当前 BTC 只展示及花费节点报告至少 6 次确认且通过本地检查的 UTXO，费率上限 500 sat/vB、总费用上限 100,000 sat；这些是拒绝异常费用的限制，不是合理市价保证。EVM 当前支持 EIP-1559 普通转账，不支持合约收款。
- 本地交易哈希先于网络广播持久化。节点超时、回包不符或广播失败时保留“不确定”状态；不能把 HTTP 成功当成链上确认，不自动重发。

## 主要威胁

| 威胁 | 现有约束与剩余边界 |
| --- | --- |
| 恶意或错误节点 | HTTPS、创世身份、原始交易/输出及节点高度哈希一致性核对、签名前刷新；单个节点仍可一致地伪造余额、费用或确认信息。不是 SPV 或完整共识验证。 |
| 节点耗尽资源 | BTC 扫描地址数、UTXO/交易数、请求数、期限及流式响应大小均设上限；触顶或中途失败就拒绝本次结果，不把部分扫描当成完整余额。 |
| 网络隐私关联 | 默认无端点、用户主动配置；RPC/Esplora 可关联 IP、多个地址、UTXO 和广播交易，链上交易公开且不可由应用删除。 |
| 收款替换 | 完整预览、地址格式与所选网络核对；剪贴板、二维码来源、屏幕覆盖及已失陷设备仍可欺骗用户。 |
| 恢复遗漏 | 明示 12/24 英文词、无附加 passphrase、固定派生路径、每分支 200 地址及 gap 20；其他路径/账户/较大间隔无法保证发现。 |
| 设备或进程失陷 | 系统钥匙串和最小权限降低暴露；越狱、恶意系统、调试注入、截图及旁观者无法由应用完全防御。 |
| 依赖与发行替换 | 锁定版本、保留许可、源码复核、构建来源、签名和独立审计；每项需要对应发行证据。 |
| 并发、重放及中断 | 一次性预览、网络绑定、nonce/UTXO 检查、持久化交易哈希；须覆盖快速点击、取消、锁屏、进程退出及断网恢复。 |

## 必须完成的发行验证

1. 已知向量：BIP39 校验、BTC BIP84 主网/Signet 描述符与地址、EVM 路径与地址、签名及交易哈希；不同 passphrase/路径不应误报为恢复成功。
2. 错误网络、HTTP、带凭据 URL、重定向、超大/畸形回包、慢响应、地址/UTXO/交易数触顶、原始交易或节点区块信息不一致、伪造费用、旧 nonce、已花费 UTXO、余额不足及不确定广播。
3. 真实 iPhone/Mac 的 Keychain 授权、拒绝、取消、锁屏、重启、无设备凭据、移除钱包及重装恢复；模拟器通过不能替代设备证据。
4. 仅用无价值 Signet/Sepolia 资金完成“恢复—备份—查询—预览—拒绝/同意签名—广播—确认—重启”闭环；不因主网代码可编译就声称主网验证完成。
5. 独立钱包安全评审、依赖/秘密扫描、最终签名包权限与隐私报告；主网资产试用须由用户明确确认，并采用可承受损失的范围。

## 报告问题

在仓库的 Security 页面使用私密漏洞报告功能（若已启用），或使用经过验证的维护者私密渠道。不要在公开 Issue、聊天、截图或崩溃附件中提交助记词、私钥、有效凭据及未公开攻击细节。发行前必须验证报告渠道实际可用并配置响应责任人；此文不虚构安全邮箱或响应时限。
