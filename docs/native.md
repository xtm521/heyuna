# Native desktop evidence and boundary

The local macOS application at `apps/desktop/src-tauri/target/debug/bundle/macos/Heyuna.app` contains its own Python/MLX runtime. It is a locally verified debug-profile alpha with an ad-hoc signature; no Developer ID signature, notarization, Windows installer, or public binary release is claimed. Rebuild it with the documented [desktop workflow](../apps/desktop/README.md).

The final application was actually launched on the development Mac. Its embedded service started over HTTPS, and the native `tauri://localhost` workspace displayed **本地服务已连接** through the Rust bridge. The native wallet displayed Sepolia, missing contract configuration, unavailable amounts and a disabled external-wallet action. A separate request verified the actual service certificate and received HTTP 401 without authentication. Native model readiness and sandbox readiness remained unavailable; no model weights were downloaded into the application's separate state directory during this check.

Each application launch creates an ephemeral certificate/key pair. Rust trusts only that certificate and disables system roots, proxies, redirects and plaintext fallback. Wrong-certificate and occupied-port regression tests verify that neither the bearer credential nor project text reaches an impersonating service. Unix certificate files are private and the temporary identity is removed during normal application teardown. Windows currently relies on the user's inherited app-data ACL and still requires device verification. Processes already able to read the user's private files, abrupt termination and crash cleanup remain separate threat/operational considerations. Explicit debug-only `HEYUNA_API_URL` and the browser preview retain their documented localhost development transport; release builds reject that override.

Packaging verified 3,244 runtime files against the staged hashes, initialized both Python TLS contexts, ran an MLX tensor smoke operation, and verified the local application signature. The frozen API was also checked with fresh temporary state: authorized status succeeds, unauthenticated status fails, and contribution starts disabled. The imported vendor Python TLS policy data is retained unchanged. All collected Python distribution-level license texts are present. The machine-readable [bundle evidence](evidence/desktop-bundle.json) contains file/source hashes and explicit limits without private keys, credentials or absolute user paths.

Browser evidence for the coding workflow, model inference, sandboxed tests, change review, apply/revert, dark mode and 200% text scaling is recorded separately in [verification](verification.md). It does not prove those full workflows inside the native package. Native system-folder-picker interaction, VoiceOver traversal, bundled 4B inference/training, Windows NVIDIA execution and independently signed distribution remain open gates. Native UI inspection was stopped when the user began interacting with the application.
