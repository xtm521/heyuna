# Heyuna research-network product design

The original Heyuna visual system is carbon black (`#090B0C`), graphite (`#111517`), silver (`#F3F5F6`) and teal (`#4FE0BA`). The primary workflow is a local coding workspace. A unified top navigation connects workspace, training, rewards, receipts and settings. Screens use compact product headings, purposeful empty states and real data; there is no duplicate welcome slogan or invented financial market surface.

`packages/design-tokens/tokens.css` defines both dark and light semantic tokens. Dark is the default only when the user has no saved preference. Existing `heyuna-theme`, `heyuna-text-scale` and `heyuna-wallet-theme` choices persist. Body text is 14px; helper text is at least 12px. Local Inter Variable (Fontsource 5.3.0, SIL OFL) is served from each app's own font assets; Chinese uses system fallback. Fonts, textures and editor resources do not require third-party network requests.

Product headings, navigation, wallet controls, empty states and promotional copy use only Heyuna branding. Compatible browser wallets appear through the standard provider interface without vendor-specific labels, logos or outbound brand links. Exact model, protocol and dependency identities remain in technical details, reproducibility records and required license notices; they must not be renamed as Heyuna technology.

## Workflow and state contracts

- **Workspace:** three adjustable panes show files, code/diff and task conversation. Pointer drag and focused Left/Right/Home/End resize the separators. Narrow layouts stack the same panels. The actual project picker remains native on desktop; localhost development uses a path dialog with focus trapping/restoration. The editor is read-only, generated changes stay in an isolated copy, Apply requires review, and Revert uses the backend conflict checks. Monaco instances are stable across ordinary state updates; diff models detach before disposal.
- **Task records:** collapsed steps describe tool requests as *issued*, not successful. Only `{exit_code, output}` test JSON determines whether the process ended successfully; this does not imply test coverage or code correctness. Unknown output stays escaped plain text. Final task states, errors and diff content remain independently visible.
- **Training:** opt-in remains off by default. Configured coordinator, authenticated connection and active training have separate labels. The page uses real contribution phase, data provenance/license/hash and sampled worker RSS/CPU. Zero/no-process placeholder resources display an em dash; actual CPU may exceed 100% across cores. No GPU progress or time estimate is invented. Stop stays available when prerequisite readiness disappears. Unsupported resource controls remain disabled.
- **Native rewards:** default tHEYUNA is the Heyuna research chain's native asset. Desktop balance stays `— / unverified`; configured backend placeholder zero is never a wallet balance. Research 297011 and accelerated-local 297012 are distinct profiles; the three-second local challenge is visibly labelled experimental. Connection and claim signature are separate explicit actions in the independent browser portal.
- **Receipts/settings:** protocol phases retain distinct computed, pending verification, verified, pending settlement, claimable and confirmed states. Unknown states remain visible. The device invitation credential is cleared after successful save and is not persisted in browser storage. Only appearance/effects preferences are stored locally.

## Original motion and compute priority

The brand mark consists of three original curved metallic ribbons converging as a sprout; the SVG static mark and Three geometry are original artwork. Lucide supplies utility icons under ISC. Layout, illustrations, text and motion are original project work. No third-party affiliation or endorsement is implied.

Motion 14.6.0 and Three 0.186.1 (`@types/three` 0.186.0) load lazily only for a positively known idle, focused, visible app. The 1.1-second opening plays once per renderer session. UI transitions are 140–200ms; scene rendering is capped at 30fps and device pixel ratio 1.5. Disposers run synchronously before task submission or contribution enable. Blur, hidden/offscreen views, reduced motion, unknown state, effects-off and computing remove the canvas, dispose geometries/materials/render lists/renderer and lose the WebGL context, leaving the original static mark. An animation never represents training progress.

## Wallet v2 trust boundary

The renderer does not gain broad shell/filesystem/API permissions. Desktop credentials remain in the narrow Rust bridge or development Vite server. External wallet navigation carries no credential. The separate portal reads a trusted public deployment manifest, not the desktop service.

A native manifest binds EVM/Cosmos chain IDs, network domain, canonical Cosmos genesis SHA256, a trusted EVM block-one anchor, runtime hashes, reward/fund/factory addresses, the contribution precompile, challenge profile and confirmations. The portal fetches Cosmos `/genesis` and verifies canonical SHA256 and Cosmos chain ID, then asks the user's EIP-1193 provider for EVM chain ID and anchor. Runtime identity, finalized epoch root/budgets, unclaimed state and full contribution-bound proof are checked before preview and again before sending. Balances are shown only after this independent read-only verification. This is not light-client consensus verification; initial manifest distribution, wallet extension and RPC remain trust boundaries.

The static portal CSP receives one exact `HEYUNA_COSMOS_RPC_ORIGIN` at development startup or build (default local research port 27657; accelerated test 28657). Only loopback HTTP origins are accepted for this release; Cosmos CORS must explicitly allow the portal. No wildcard or general arbitrary HTTP permission is introduced. EIP-1193 extension traffic stays inside the wallet provider. Native claim uses zero transaction value with native fee estimate, a distinct confirm/sign step, event matching including contributionId, canonical receipt block and claimed-bit check. V1 ERC-20 remains an explicit imported legacy adapter and never silently replaces v2.

## Accessibility and evidence

Controls have visible focus and labels, dialog focus restoration, keyboard resize, plain-text model output, live status/alert regions, reduced-motion support, light/dark themes and 100–200% text scaling including code/diff. Desktop 1440px and narrow 390px layouts, theme/scale changes, real local API states, resource disposal and read-only actual-chain identity are separate QA entries in `apps/desktop/evidence/qa-inventory.md` and the accompanying verification record. Headless EIP-1193 adapters are test fixtures, never evidence of a user wallet signature.

Renderer build/test/screenshot results remain distinct from a rebuilt native bundle, operating-system focus behavior, real 4B inference, multi-device training, model quality, independent validators and settled rewards. Previous native build evidence does not imply that the new design has been packaged. Mainnet and security-audit gates remain unchanged.
